模型后训练从已有权重出发，用示范、偏好或任务结果调整模型行为。SFT、RLHF、DPO 与 RLVR 主要讨论训练信号和优化方式；LoRA 与 QLoRA 则讨论参数更新及存储方式。理解它们的关系，首先要把“根据什么学习”和“允许哪些权重变化”分开。

RLVR 使用可验证结果作为奖励，让策略在生成、评分和更新中提高相应行为的概率；LoRA 冻结底座，在选定层训练低秩增量。两者可以组合为 LoRA RLVR，也可以分别与其他选择组合。资源节省并不改变奖励需要可信、任务需要独立评测的责任。

这条区分在公开训练配方中有具体参照：Tülu 3 将 SFT、DPO 与 RLVR 组合，TRL 的 GRPOTrainer 将奖励函数与 PEFT 配置作为不同输入。下文先建立训练信号和参数选择的整体，再分别下钻低秩分支、策略更新和执行环境。

## 后训练先决定用什么反馈

预训练让模型从大量语料中学习 token 的条件分布。后训练从已有权重继续出发，用更有针对性的材料和目标调整行为。“按指定格式回答”“更倾向于正确结果”“接受哪种表达方式”，可以由不同训练信号推动。这些变化仍可能影响其他任务，训练之后需要重新评测。

SFT，即监督微调，提供题目与期望回答。训练材料是一条输入配上正确示范，模型学习在相应上下文中提高示范 token 的概率。常见目标是把参与监督的回答 token 的负对数概率相加；哪些位置参与求和由数据和 loss mask 决定。例如只训练回答部分时，题目提供条件，不同时作为要复述的目标。

SFT 的明确优势是有一条可模仿路径。模型还不懂指定 JSON 格式时，正确示范直接告诉它目标输出的样子。相应地，团队要负责示范质量。格式错误、答案错误或数据泄漏都会进入监督信号。

偏好材料提供另一类信息：同一道题的回答 A 和回答 B，哪一个更好。经典 RLHF 路线先用人类比较训练奖励模型，再让策略生成回答，由奖励模型打分，经过强化学习调整策略。InstructGPT 公开研究里的示范微调、排序奖励模型和 PPO 更新，是这一经典链路的例子。RLHF 说明人类反馈的来源和作用，具体系统可以采用不同训练配方。

DPO 直接利用偏好对。经典离线 DPO 比较 chosen 与 rejected 回答在当前策略中的相对概率，并用参考策略的概率作校准。训练目标鼓励所选回答相对参考策略获得更大的概率优势。因此，它通常无需另外训练显式奖励模型，也无需在每个更新步骤在线生成新回答；但仍需要质量可靠的偏好对，以及用于目标计算的参考概率。参考模型可以通过具体实现复用、预计算等方式处理，不能只根据算法名称推算设备数量。

对于数学、代码或规则明确的指令任务，还存在可以执行的正确性检查。RLVR 的全称是 Reinforcement Learning with Verifiable Rewards，即使用可验证奖励的强化学习。策略自己生成回答，外部程序检查格式和结果，再把得分用于更新。代码任务可以通过测试得到信号，数学任务可以检查最终答案，交互任务可以检查环境的终止状态。规则所覆盖的成功条件决定了模型受到什么激励。

| 路线 | 同一道题要准备的材料 | 监督或评分的对象 | 常见训练入口 |
|---|---|---|---|
| SFT | 题目和正确示范 | 示范回答中的 token | 离线监督训练 |
| 经典 DPO | 题目、chosen、rejected | 两条回答的相对偏好 | 离线偏好对优化 |
| 经典 RLHF | 人类比较，以及可供策略采样的题目 | 奖励模型给生成回答打分 | 奖励建模与策略优化 |
| RLVR | 题目和可执行的成功规则 | 策略生成的回答或轨迹 | 规则评分与策略优化 |

例如 Tülu 3 的 RLVR 使用 GSM8K、MATH 与可自动检查约束的 IFEval 任务：题目及答案或规则支持验证，策略在训练时生成候选。SFT 数据预先提供要模仿的回答，偏好对预先提供相对选择，RLVR 则从当前策略产生的行为取得奖励。它们向学习过程交付的材料不同。

从正确 rollout 中筛选样本，再把它们做成 SFT 数据，也是可用的训练路线，但更新目标已改变：SFT 模仿留下来的序列，策略优化利用奖励相对基线的差异决定更新方向。仅看到训练数据来自模型生成，无法判断系统采用了哪一种目标。需要继续查看 loss 怎样计算，以及失败候选是否参与形成信号。

这张表是训练材料与常见路线的对照，几行并非完全互斥的算法分类。RLHF、RLVR 强调反馈来源；DPO、PPO、GRPO 等名称进一步说明信号怎样进入优化过程。公开的 Tülu 3 配方组合了 SFT、DPO 和 RLVR；DeepSeek-R1-Zero 则研究过从基础模型直接做 RL 的路径。两者说明后训练可以组合，并不存在所有模型必须遵循的单一顺序。

SFT 可以先建立格式与交互行为，再由 RLVR 优化可验证成功；直接从基础模型开始 RL 也是已研究的路线。选择取决于初始策略能否产生可被奖励区分的候选。验证器能判题，不保证模型已经具备值得强化的成功行为。

## 把训练信号与参数选择放在两条轴上

![二维表分别列出 SFT 和 RLVR 训练信号，以及全参数与 LoRA 更新方式的四种组合](/assets/images/posts/rl-post-training-environments-mechanism.png)

图中横纵两项分别决定反馈和参数更新。沿任意一种反馈都可以选择全参或 LoRA；切换到 LoRA 后，原来的任务、监督规则和评测责任仍然存在。

| 配方 | 准备什么训练材料 | 优化信号 | 可训练对象及主要代价 |
|---|---|---|---|
| 全参 SFT | 题目和正确 JSON 示范 | 示范 token 的负对数概率 | 全部训练权重；梯度与优化器状态较多 |
| LoRA SFT | 相同示范 | 相同监督目标 | 选中层 A、B；底座前向与激活仍在 |
| 全参 RLVR | 题目、候选生成和严格验证器 | 结果奖励形成的策略梯度 | 全部策略权重；另有 rollout 和评分成本 |
| LoRA RLVR | 相同任务与验证器 | 相同奖励路线 | 选中层 A、B；仍需生成、评分与策略概率计算 |

经典离线 SFT 的每个更新步骤可以直接使用示范，不必像在线 RL 那样先生成一组新候选。示范的收集当然有成本。LoRA RLVR 则仍要探索候选、运行验证器、保存训练序列，不能用一个小 adapter 文件替代这些工作。TRL 当前稳定版 v1.16.0 的 GRPOTrainer 仍分别接受 `reward_funcs` 和 `peft_config`，并实际通过 PEFT 包装策略模型，体现这两条轴可以组合。

效果选择也要分开。示范足够可靠、主要目标是学会格式与已有行为时，可先测 SFT。成功条件能低成本自动检查、初始模型已有一定成功候选时，RLVR 有可操作的信号。可训练状态超出预算时，再考虑 LoRA；若目标变化需要更大的更新空间，则要比较目标层、rank 和全参更新，而不能预设 adapter 与全参在所有任务上等效。

## LoRA 决定梯度写进哪里

无论采用哪一种训练目标，反向传播最终都要确定哪些参数接收更新。全参数更新允许选定模型的全部训练权重变化；LoRA 在选中层增加可训练的低秩分支，原权重保持冻结。相同的 SFT、DPO 或 RLVR 信号，都可以进入这个分支。

对一个线性层，输入向量 `x` 长度为 k，输出长度为 d，原权重 `W₀` 的形状是 `d×k`。标准 LoRA 增加两个矩阵：`A` 为 `r×k`，`B` 为 `d×r`。前向计算为：

```text
h = W₀x + (α/r)BAx
```

A 先把输入映射到 r 维，再由 B 映射回 d 维，得到与原层输出同形状的增量。`BA` 的秩至多是 r；低秩约束施加在权重改变量上。原始权重矩阵仍然存在，输出维度也仍是 d。

### rank、alpha 和目标层分别控制什么

一个 `4096×4096` 的线性层有 16,777,216 个权重。取 `r=8`，A、B 一共有 `8×4096 + 4096×8 = 65,536` 个参数，是这一个矩阵权重数的 0.390625%。这个比例只是单层参数复算。整个模型还可能包含其他模块，显存也有其他组成，不能把它直接当作模型显存比例。

rank 决定低秩增量的表达空间和参数规模；alpha 决定分支缩放。在标准 LoRA 中，缩放系数为 `α/r`。固定 alpha 改 rank，会同时改变容量与缩放，因此观察结果变化时需要检查两个因素。某些变体采用不同缩放，例如 rsLoRA 使用 `α/√r`，阅读配置时应先确认具体方法。

`target_modules` 决定哪些层加分支。部分模型的注意力层使用 `q_proj`、`v_proj` 等名字，其他模型的模块结构可能不同；模型架构、目标层覆盖与 rank 共同决定训练对象。只改两类投影和覆盖全部线性层，成本与更新空间差异很大。

冻结也需要实际配置。标准解释假定原权重不参与梯度更新；PEFT 中的 bias、`modules_to_save` 等选项还可以让其他参数训练。应检查最终哪些参数可训练，而不能看到 LoRAConfig 就认定所有非 A、B 参数都冻结。优化器只为允许训练的对象维护状态，配置错误可能同时改变内存和行为。

### 零输出分支怎样开始学习

常见初始化让 A 有非零初值、B 为零。此时 `BA=0`，插入 adapter 后原层的输出不变。B 虽然为零，仍可以收到梯度；A 的梯度在第一步可能为零，等 B 改变后才有信号。

用一个可复算的小层说明这个过程。W₀ 取一个 `3×4` 矩阵，前三列为单位阵，第四列为零。取 `A=[1,−1,2,0]`、`B=[0,0,0]ᵀ`、`x=[2,1,3,4]ᵀ`，并令 `α/r=2`。此时 `Ax=7`，原层输出为 `[2,1,3]`。

若教学损失是相对零向量的平方误差之和的一半，B 三个元素的梯度分别为 `[28,14,42]`，A 的梯度全为零。有限差分复算与此一致。它说明零初始化的输出分支具有起步的梯度路径；这个小矩阵计算没有进行 Transformer 训练或优化器更新。

再把 B 手工设为 `[0.5,−0.5,1]ᵀ`，增量输出为 `[7,−7,14]`，最终得到 `[9,−6,17]`。对于标准线性分支，也可先算 `Wmerged=W₀+(α/r)BA`，再做一次矩阵乘法，得到相同结果。这个等价性支持在合适条件下合并权重；量化、舍入和额外变体仍需检查，不能从精确小矩阵推出所有部署路径数值完全相同。

### QLoRA 进一步改变底座存储

训练显存大致来自底座权重、可训练参数的梯度、优化器状态、激活与中间张量，以及生成缓存和运行缓冲。强化学习还可能使用价值模型、参考策略、奖励模型或独立推理服务，各项可能分布在不同设备和阶段。

LoRA 主要省去大量冻结权重的梯度和优化器状态。底座仍要加载并参与计算，通往 adapter 的计算路径仍需要激活；长序列或较大的候选组可能成为主要开销。文件里的 adapter 很小，并不足以推断某张卡能训练整个系统。

QLoRA 在此基础上，把冻结底座用低比特形式存储，并通过该计算路径训练 LoRA。原始方案包括 NF4、量化常数的再次量化和分页优化器等设计；计算可采用 BF16，adapter、梯度和所有中间量并不会一起变成 4 bit。它进一步处理的是底座存储与训练内存问题，训练目标或优化信号仍可以来自 SFT、偏好或可验证结果。

因此，估算设备预算时应同时列出模型加载精度、序列长度、每题候选数、目标层与 rank、优化器、是否有额外模型，以及生成与训练是否分离。实际峰值显存与吞吐要由对应模型和运行栈测量，单层参数比例不能代替容量规划。

## RLVR：外部奖励怎样改变生成概率

先把模型视为策略 `πθ`。给定题目和已生成的前缀，它为下一个 token 提供概率；θ 表示允许参与计算的模型参数。一次 RLVR 更新需要把生成、打分和训练连接起来。

每批开始时，训练系统固定用于采样的策略版本，记作 `πold`。同一道题生成 G 条候选回答，称为一组 rollout。除了文本，还要保留生成 token 和它们在旧策略下的 log probability。交互任务还需要动作、观察、终止原因等轨迹。只有“这一题做对了”的文字记录，无法替代训练所需的概率与序列信息。

验证器随后对每条候选打分。为把 TRL 奖励函数所承担的映射写清楚，可以定义一个数学教学模型：输入整数列表 `[-7,12,5]`，要求输出 `{"answer":10}`。本节的候选奖励是公式输入，不是训练观测。评分规则是：能够解析为唯一字段的 JSON 对象，`answer` 的类型是整数，数值等于输入之和，记 1；其他输出记 0。这把格式和正确性合在一个二值奖励中。实际系统可以分别给分，权重如何设置会改变行为目标。

### 从奖励到组内优势

同一道题的四个预设候选得到奖励 `[1, 0, 1, 0]`。正确回答应该提高多少概率，需要一个比较基线。GRPO 使用同题的一组结果形成相对信号，可以省去另行训练的价值模型；代价包括每题多个候选的生成开销，以及组内比较本身的方差。

一种常见的组优势计算是：

```text
Aᵢ = (rᵢ − 组内平均奖励) / (组内奖励标准差 + ε)
```

`rᵢ` 是第 i 条候选的奖励，`Aᵢ` 是它相对于组内基线的优势。以下复算固定采用 TRL v0.29.1 一段聚合路径的计算口径：使用样本标准差，分母加 `0.0001`。上述四条奖励均值为 0.5，标准差约为 0.57735，因此优势约为：

```text
奖励：  1          0          1          0
优势：  0.865875  −0.865875   0.865875  −0.865875
```

采用总体标准差会得到不同数值，不能把两种口径混在一张结果表中。训练器也可以选择只去中心化、不按标准差缩放；优势公式属于具体配方，不能根据“GRPO”这个名称假定全部默认值。

在只给最终结果奖励的这一示意中，同一条回答的生成 token 共享该序列优势。正优势鼓励提高这条采样序列的概率，负优势鼓励降低它。奖励没有指出“第几个 token 算错了”；训练借助采样序列的概率，把结果信号分配到参与生成的参数上。

如果四条回答全错，或者全对，去中心化后的优势都为零。这意味着该组在这个相对奖励项上缺少区分信号。全错可能来自题目太难、格式不会、评分器错误或环境故障；全对则可能意味着题目过于简单。零优势不自动等于整个训练 loss 为零，因为系统可能还有其他项或其他任务。

### 从优势到可微目标

接下来，当前策略重新计算这些已采样 token 的概率。对第 i 条回答的第 t 个 token，定义：

```text
ρᵢₜ = 当前策略给该 token 的概率 / 采样策略给该 token 的概率
```

两次计算必须使用对应的题目、前缀和实际生成 token。`ρ` 表示同一采样动作在更新后变得多常见。训练系统利用 `ρA` 构造目标；优化器经反向传播计算梯度，才能把外部的一分奖励转成权重变化。

PPO 的 clipped objective 及原始 GRPO 使用的相关形式，会限制反复利用同一批采样时的更新诱因。一个用于解释的单项是：

```text
Jclip = min(ρA, clip(ρ, 1−c, 1+c) × A)
```

这里 `c` 是裁剪宽度，与优势分母中的小常数 ε 分开。取 `c=0.2`：若 `A=1`、`ρ=1.4`，两项为 1.4 和 1.2，取 1.2，继续提高这条正优势回答的概率不再从该分支得到同样收益。

负优势也要按符号判断。若 `A=−1`、`ρ=0.6`，两项为 −0.6 和 −0.8，取 −0.8。它抑制沿着“降低负优势回答概率”的有利方向无限推进。这个机制改变的是目标的梯度诱因，不能把它解释成所有模型概率比都被硬性锁在区间内，更不能把裁剪当作答案正确性的保证。

原始 GRPO 还包含相对参考策略的 KL 惩罚，用于给偏离参考分布增加代价。此时有两个作用不同的参照：`πold` 是这一批样本的采样策略，用作概率比分母；`πref` 是分布锚点，用于 KL。它们可能从同一初始权重出发，但随训练推进承担不同职责。

KL 是否启用必须看配方。TRL v0.29.1 的 GRPOTrainer 文档中，`beta` 默认是 0，此时不加载参考模型。不能拿原始论文的目标式，推断某个训练器始终计算 KL；也不能断言组奖励相同时一定只剩 KL 把模型拉回。

当前 TRL v1.16.0 的实现还区分多种 loss、token/sequence 重要性比及归一化选项。因此，选择训练器时应固定具体目标与配置，不宜把下面的共通流程当作所有版本的完整 loss。

完整一轮因此是：旧策略采样候选，验证器形成奖励，奖励转成优势，当前策略重算 token 概率，以裁剪项及配置中的其他项构造目标，取负形成 loss，反向传播，优化器更新可训练参数，再用新策略生成下一批候选。原始 GRPO 与后续实现还存在归一化、重要性修正等区别；这条链路解释共同对象和职责，不代替某个训练版本的完整公式。

## 验证规则决定模型受到什么激励

求和规则很容易写错。例如用 `'10' in output` 检查答案，字符串 `not 10` 也会得到满分。这个程序检查了子串存在，任务定义却是结构合规且整数答案正确。若把它作为优化目标，训练系统就会奖励错误行为。

下面是该教学任务的完整判分函数。它特意拒绝重复 JSON 字段，并把布尔值与整数分开，避免 Python 中 `bool` 属于 `int` 子类带来的歧义。

```python
import json


def unique_object(pairs):
    obj = {}
    for key, value in pairs:
        if key in obj:
            raise ValueError("duplicate key")
        obj[key] = value
    return obj


def reward(text, operands):
    try:
        obj = json.loads(text, object_pairs_hook=unique_object)
    except (ValueError, TypeError):
        return 0
    return int(
        isinstance(obj, dict)
        and set(obj) == {"answer"}
        and type(obj["answer"]) is int
        and obj["answer"] == sum(operands)
    )
```

对输入 `[-7, 12, 5]`，`{"answer":10}` 得 1；错误整数、`not 10`、重复字段、布尔值、额外字段和 `10.0` 都得 0。拒绝浮点数来自本任务的格式要求，换成允许数值等价的任务，就应调整规则。

这个判分模型展示规则怎样与目标对应。真实 reward hacking 指模型在优化中利用奖励缺陷的行为，需要训练轨迹支持；单纯列出坏评分函数不能证明已经发生。严格的最终答案检查也只验证答案和格式，不能证明模型生成的每一步解释正确。

终端任务把这个问题放大：模型可能修改测试、读取标准答案，或者把一次环境超时误当普通失败。评分器和隐藏数据应置于候选无法修改的边界。缺少奖励的基础设施错误需要单独记录；把它直接填为 0，会让训练把服务故障误解为该策略的错误。

## 环境把任务、执行和评分接到训练器

前面的数学模型只需题目和函数调用。OpenEnv、Harbor 等交互任务还让候选写文件、调用工具、运行检查并改变环境状态。训练系统需要保证每条轨迹有清洁起点，动作受到明确限制，评分条件也保持一致。

Hugging Face 在 2026 年 9 月发布的 RL Environments 发现入口，沿用数据集仓库组织 taskset，并提供框架标签。这使任务资源更容易发现和识别；标签本身不启动隔离运行时，也不把不同框架的文件自动转换成可执行环境。加载任务、跑一次策略和更新权重，是三项相互衔接的工作。

| 对象 | 持有的主要材料或状态 | 向下一环交付什么 |
|---|---|---|
| Taskset | 题目、初始文件、任务划分和版本 | 一个确定的任务实例 |
| Runtime | 工具、进程、动作权限与资源限制 | 观察、退出状态和交互轨迹 |
| Verifier | 隐藏答案、测试和评分规则 | 奖励，或明确的评分故障 |
| Trainer | 策略、旧概率、可训练参数与优化器 | 新权重或 adapter，以及训练指标 |

OpenEnv 的官方端到端教程提供了一条具体交接：`reset` 给出初始任务，模型生成动作，包装层把动作交给环境 `step`，环境返回观察和 `done/reward`，训练器消费轨迹与奖励并更新策略。训练器拥有权重和优化器，环境拥有执行状态，评分器定义成功条件。

在终端案例中，如果候选一留下修复文件，候选二继续使用同一个目录，就可能不经努力获得成功。组内奖励的比较前提已被破坏。若 Agent 能修改评分脚本，同样可能提高 reward 而没有改好目标程序。因此，清洁重置、评分器保护和任务版本固定，应进入训练设计，而不能只留在日志里。

## 先验证奖励，再判断训练是否有效

启动训练之前，先用参考解跑通任务，确认正确结果得正分；再用错误答案、异常格式、超时和评分器故障检查其他分支。这一步在测试测量工具本身。评分器不可信时，增加训练步数只会更认真地优化错误目标。

随后固定初始策略跑基线，分别看格式合规、结果正确、环境失败与超时。求和模型若总因格式得零，而正确示范容易取得，SFT 能提供明确的行为入口。模型若偶尔成功，可靠验证器就能为 RLVR 提供有差别候选。组内几乎总是同分时，先查任务难度、初始能力和评分实现，再调整采样与训练。

最后把训练和评测分开。留出任务既不参与权重更新，也不参与奖励规则反复调参。求和任务可以按项数、负数比例和数值范围划分，说明测试哪种外推；终端任务应按项目或题型检查重复与答案泄漏。只把训练题换一个顺序，通常不足以建立独立证据。

比较初始策略与训练后 checkpoint 时，应固定解码预算、工具权限和评分器版本，同时报告成功率、失败类型以及生成和执行成本。若训练后给了更多采样次数，额外预算本身也可能带来更高通过率，不能全部归因于权重更新。训练 reward 上升说明模型更符合该训练测量，留出结果才进一步回答需要的能力是否改善。

反馈规则可信、初始策略可达、任务能够独立评测之后，再按预算选择全参或 LoRA。这样的顺序把奖励设计、优化算法和参数规模各自负责的决定保留下来，也让一次训练失败时有具体对象可查。
